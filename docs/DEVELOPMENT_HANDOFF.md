## このチャットから引き継ぐ合意と判断

- **完成像は広く保つ。** 最重要3作品を継続して学び、今の人数・一軒の家・画風・画面・保存構造を完成形の制約にしない。小範囲の実装は比較と検証の単位。
- **実装後は最終成果物を実際に遊ぶ。** 実装 → ビルド → 実試遊 → 必要な修正 → 影響箇所の再確認 → 納品。通常開始と人工保存の境界確認、修正前と最終版、PC/スマホ幅と実機を分けて報告する。
- **H6bの採用範囲は一束の準備と運搬。** 一担当・一床・野菜2の一束、直接指示と生活の優先、途中保存を実装した。停止・解除は次回の補充を止め、進行中の運搬は続く。自動運搬の明示取消や返却受理では方針も停止する。返却を取り消しても停止は残る。自動調理や一般物流の採用を意味しない。
- **GitHubはPublicで継続保存する。** ユーザー本人の公開設定を尊重し、以前の非公開化・本人確認待ちを再開条件へ戻さない。詳細証拠106ファイルの追加送信保留は別に維持する。
- **Docs7のため、機能単位のブランチ → PR → 確認後mainへ統合を標準にする。** 2026年11月26日にユーザーが明示採用した。関連文書を同じPRへ含め、Docs7の指摘と開発側の検証を確認する。自動マージ・課金・Hosting公開を追加した合意ではない。
- **GitHub・Notion・検索・配信を分ける。** NotionとGitHubは自動同期されないため、実際の保存版と判断を手動で揃える。Docs7の文書支援をゲームの試験や実試遊の代わりにせず、GitHub保存をSites公開と混同しない。

The Sims 4・RimWorld・Kenshiを最重要の参考作品とし、他のテキスト型シミュレーションからも継続して学ぶ。一人の住人としての生活と、仲間・拠点・部隊の運営をつなぎ、生活、人物関係、建築、生産、物流、成長、探索、戦闘、社会が影響し合うゲームを目指す。

## 直近H6b：一束の補充担当

「住まい」で選んだ住人と床を保存し、生活や進行中の行動を優先したうえで、一束がなくなったら共有食材2を取り分けて実際に運ぶ。現物中は二重に作らない。停止・担当解除は現在の運搬を完了させ、自動運搬の明示取消や返却は補充方針も停止する。旧保存には方針を追加しない。料理と設備の明示指定、共同備蓄からの料理は維持する。

## 前工程：一束の食材の保管・運搬・料理

「住まい」で歩ける保管床を選び、共有食材2を居間入口の野菜一束に取り分ける。担当に実搬送を指示し、「暮らし」の基本料理で材料に一束・設備にかまど／台所を明示指定する。料理人は拾得、搬送、加工を行う。加工完了で食事を得て束を消費する。取消は現物を床または区間の終点へ残し、供給口に戻してから共同備蓄へ返す。共有料理と自主行動は従来どおり。旧保存に新台帳を自動追加しない。最終統合レビューで保管済みの一束の返送不能理由が隠れる問題を修正した。候補から住人を選んで方向別の理由を読めるが、無効な実行は本体予告・検証で防ぐ。

制御した10条件では、本人が自分で入庫して料理すると共同備蓄からの料理より4～18分長く、指示は1→3回。助手による入庫後に同じ開始条件で料理した比較では、近炉に近床から運ぶと14分、遠炉に遠床から運ぶと4分短縮した（各炉について反対の床から運ぶ場合との比較）。助手の準備4／9分と、条件合わせの料理人の待機10分も別計上した。加工時間35分と産出は全条件同じ。配置・分担が動線に影響することと、生産効率上の利益は区別する。
