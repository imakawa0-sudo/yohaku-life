## 1. The Sims 4：指示・到着・入室条件を分ける

資料：[EA公式 Small Business案内](https://help.ea.com/en/articles/the-sims/the-sims-4/how-to-set-up-a-small-business/)

日付：ページ表示は「7か月前に更新」。正確な更新日・初出日は不明。対象はBusinesses & Hobbies拡張パックのSmall Businessであり、全パック共通の内部処理を説明する資料ではない。

確認事項：従業員に指定した仕事はシフトに到着すると自律的に行われる。居住用・公開・従業員専用の区画では、来客と従業員が入れる範囲が異なる。雇用されていない世帯員にも事業の仕事を指示できる。

H1-Bへの提案：行動の受付、現地への到着、現在の利用許可、実際の作業開始を区別する。将来の役割や雇用制度を、人物の所在や一時的な指示そのものに埋め込まない。原作の人数・仕事件数制限を本作へ移植する根拠にはしない。

## 2. Kenshi：予約の残骸と保存後の所在を重点確認

資料：[Lo-Fi Games公式 Patch Note Archive](https://lofigames.com/patch-notes/)

日付：古い資料（1年以上前）。HTMLメタデータは2022-02-15公開、2022-02-22更新。以下の各パッチの初出日は今回特定していない。

確認事項：0.93.11には、早くベッドを出ると使用中扱いのままになる問題の修正がある。0.95.9には、運ばれている人物を読み込んだ際、世界内のランダムな地点へ落ちる問題の修正がある。

H1-Bへの提案：取消・完了・読込みのたびに、人物の仕事と設備予約の対応を確かめる。保存直前の所在を再計算で作り直さず、継続可能な状態として保存する。試験には「取消後に別人が同じ設備を使える」「運搬途中の保存後に対象が消失・重複・別地点へ移動しない」を加える。

限界：この記述から現在の予約データ構造、全行動の自動再開条件、マルチタスク方式は確定できない。

## 3. RimWorld：一つの失敗が仕事全体や既存建物を巻き込まない

資料：[Ludeon公式 Update 1.6.4850 released](https://ludeon.com/blog/2026/06/update-1-6-4850-released/)

日付：本文署名は2026-06-08、Tia Young。確認日から1年以内。この版の更新記事を参照しており、これが最新安定版であるという確認は行っていない。

確認事項：資源の搬入仕事の問題で住民が仕事を一切受けなくなる不具合が修正された。また、既存の壁を置き換える設計図を取り消すと、既存の壁の付属物まで消える不具合が修正された。

H1-Bへの提案：一つの仕事が実行不能になった場合、状態を理由付き待機として残すか取り消すかを明示し、無関係な後続行動まで永久に拒否しない。取消ではその仕事が確保したものだけを解除し、元の建物・在庫・他人の予約を巻き込まない。

## 4. CDDA：開始・進行・完了・取消と再開を別の処理にする

資料：[Cataclysm: Dark Days Ahead公式開発文書 PLAYER_ACTIVITY](https://docs.cataclysmdda.org/PLAYER_ACTIVITY.html)

日付・版：日付表示を確認できない継続更新の開発文書。今回取得した内容を扱う。特定の安定版への対応や最終更新日は未確認であり、「1年以内に更新された」とは断定しない。

確認事項：activity_actorにはstart、do_turn、finish、canceledの役割がある。startは割当時に一度呼ばれる。cancel_activityはfinishを実行せず、再開可能な仕事をbacklogへ残す場合がある。完了した仕事でcancel_activityを呼ぶと、完了済みの仕事を再開できる状態が生まれ得るため、文書はset_to_nullまたは新しい仕事への切替を指示する。実行に必要な対象・位置などを保存し、NPCが使う座標はプレイヤー相対の局所座標ではなく絶対座標にする注意がある。

H1-Bへの提案：既存Taskを読み込んだ際に「開始処理」を再実行しない。費用・材料の確保、進行、効果の確定、取消時の戻しを区別する。新しい空間処理の完了通知は、既存の完了処理へ一度だけ渡す。保存形式には途中段階と、既に確保した資源の情報を残す。

## 受入試験へ落とす提案（本作向けの判断）

1. **時間と到着**：指示直後は時計・実位置・利用効果が変わらず、到着前には設備利用が成立しない。到着時間に利用時間を二重計上しない。
2. **旧Taskの継続**：材料を確保済みの旧セーブを読み込み、残時間・元の予約・game/origin・外見を保持する。開始費用を再徴収せず、完了効果も一度だけ確定する。
3. **分割と再読込み**：一括進行と、途中保存・再読込みを挟む分割進行で、最終時刻・所在・在庫・完了回数が一致する。
4. **待機と復帰**：経路・許可・設備の競合で待つ理由を表示でき、条件が戻れば同じ仕事を残時間から再開する。新規に発行し直して資源を再予約しない。
5. **取消**：利用前・利用中・移動中で取り消す。仕事専用の予約だけが解除され、他の人物や既存設備を保持する。取消途中で保存しても元の目的を再開しない。
6. **未確定の旧位置**：旧セーブにない室内マスを読込み時に事実として捏造しない。実行可能な位置へ移す方針が必要なら、設計上の移行規則として明示する。
7. **操作の説明**：「移動中」「到着後の利用」「待機と理由」「取消して退出中」を画面から区別できる。見た目だけの進捗とゲーム内の実状態を分離しない。

これらは原作内部処理のコピーではなく、公式に説明された行動や失敗例を本作の受入条件へ変換した提案。H1-Bの実装範囲は現行コードと既存の保存契約を照合して決める。

## 別タブで同時に保存する場合の技術確認

2026-11-23にFirecrawlで以下の一次資料を最新取得（HTTP200）し、同じページをブラウジング用の読取りでも照合した。

- [WHATWG HTML Standard：Web storage](https://html.spec.whatwg.org/multipage/webstorage.html)。ページの更新表示は2026-11-22。localStorageの読取りと書込みについて、複数プロセス間のロックがあると仮定しないよう説明している。したがって、保存直前に元の文字列を比較するだけでは、二つのタブの読取りから書込みの間に競合する余地が残る。
- [W3C Web Locks API](https://w3c.github.io/web-locks/)。2026-11-12付のEditor’s Draft（編集中の仕様）であり、確定した推奨仕様という意味ではない。同じ保存領域に属するタブ等が、名前を付けたロックで作業を協調できる。navigator.locksは安全なコンテキストに公開され、requestのコールバック内で処理を行い、終わると解放する。

本作での判断：同期の保存関数は直前照合と結果分類に集中させ、画面からは小さな非同期ラッパーで保存する。対応環境では同じ名前の排他ロック内で照合と書込みを行う。APIがない場合の直前照合は残すが、同時に複数タブを操作しない案内を表示する。取得が失敗した場合は保存不可として扱う。旧コードや手動による保存編集も含めた完全な排他を保証するという説明はしない。
