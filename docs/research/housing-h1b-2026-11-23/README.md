# 住居H1-B：実位置を暮らし・操作・保存につなぐ

2026-11-23（台湾）。基準はGitHub main `a8e6a6b387658253c636e57689acb67fa179e1e8`。H1-Aの空間処理を、住居での設備利用と料理、待機・取消、既存ゲームの時計、保存へ接続する工程。

The Sims 4・Kenshi・RimWorldとテキストシミュレーションから学び、生活・人間関係・生産・建築・冒険が結び付くシミュレーションストラテジーRPGを目指す。現在の名称、画風、人数、拠点数、4タブ、時間の刻みは試作上の具体化であり、完成形の規模を制限するものではない。

## 今回の機能と意味

| 機能                   | ゲーム内の意味                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 住居内の実際の位置     | 家具のマスは通り抜けず、隣接する床へ歩いてから設備を使う。部屋に向かう予定と、そこに到着した事実を区別する。                                                   |
| 到着と利用の別進行     | 歩いている間に食事や料理が完成しない。利用残りと、移動を含む完了見込みを分けて扱う。                                                                           |
| 理由のある待機         | 通路が閉じている場合と、部屋や設備の利用許可がない場合を区別する。条件を戻して時計を進めると、同じ仕事を続ける。                                               |
| 途中取消               | 通路の途中なら今の区間を出てから取り消す。その仕事が取り置いた材料を一度だけ戻し、完成効果は出さない。                                                         |
| 安全に行える間取り編集 | 現在地、移動の着地点、進入済み通路、予約した設備と利用位置を壊す編集は拒否する。木材を使う前に理由を返す。無関係な編集や、保護対象を残した近道の追加はできる。 |
| 実際の同席             | 自宅で新しく組行動を始めるときは実際の同地点を確認する。共食は同じ利用位置で時間が重なった記録から、各自の食事完了時に各自へ一回ずつ反映する。                 |
| 旧保存から選べる分岐   | 元の暮らしを残して住居の移動を使う暮らしへ分岐する。進行中だった旧行動の時間と材料を再計算しない。                                                             |

通路や利用許可を設定してもゲーム時間は進まない。時計を進める入口は従来の`advance`に集約し、1分ごとに全住民の空間状態を一回だけ更新する。画面の見積りと指示はゲーム本体の同じ判定を使う。

社交設備の効果は、本人が設備を使った1分間の開始・終了とも相手が同じ地点にいたことを記録してから決める。指示時だけ相手がいた場合や、通り過ぎただけの場合は会話として数えず、観測がない場合は手紙の効果と描写になる。観測は途中保存をまたいで保持する。自主会話・手当てでは、先に並ぶ別室の相手を除き、実行できる相手を探す。

## 旧保存をどう保つか

新しい手帳は保存キー`yohaku-reform-library-v2`と`Library.format = 2`を使う。旧キー`yohaku-reform-library-v1`は読み取り元として保持する。新しい手帳がない場合だけ旧手帳をメモリーへ複写し、最初の書込みまでに旧手帳が変わっていないかも照合する。新しい手帳が壊れているときに、黙って古い手帳へ戻ることはない。

単なる手帳の複写では、旧保存のゲーム方式を変えない。明示した住居用の分岐だけが別IDの暮らしを作り、現在状態と最初の朝を、それぞれの元の内容から独立に初期化する。通常の「同じ朝」「今の時点」の分岐は元の方式を引き継ぐ。

旧保存には正確な室内マスや、途中仕事の移動・利用の内訳がない。そのため読込みだけで位置を入口へ動かしたり、材料をもう一度確保したりしない。次に受理する住居内の新しい指示で、現在の部屋の入口を初期位置にする。無効な指示や表示だけでは位置を確定しない。旧作業の保護に使う通路列は互換継続のための依存情報であり、過去の実経路を復元した記録ではない。

住居情報を含む書出しは保存の包みをversion2とし、含まない旧保存の書出しはversion1を保つ。version1へ住居情報を混ぜた入力や、最初の朝だけが壊れた入力も拒否する。

さらに、分岐や名前の整理を終えた手帳が読めることを、実際に書き込む前に検証する。旧方式では受け入れられた設備の席などを新方式へ忠実に変換できない場合は、理由を示してその分岐を断る。元の旧暮らしと無関係な保存枠はそのまま再開・書出しできる。

## 二つのタブで操作した場合

保存前に前回読んだ文字列と現在の保存を照合し、更新・削除・不正な保存を検知する。対応ブラウザではWeb Locksも使い、協調する新版タブの照合と書込みを順番に行う。負けた操作は最新状態へ切り替えて再操作を案内し、古い計算結果を保存しない。

Web Locksがない環境では直前照合を使い、複数タブの同時操作を避ける案内を表示する。この場合の完全に同時な書込みを排他したという説明はしない。ロック取得や保存自体に失敗した場合は、保存できない状態と案内を返す。旧コードや外部からの保存編集は同じロックを取らないため、ロックの保護範囲外である。

## 次につなぐ範囲

今回でH1全体や住居・建築・居住環境を完成とはしない。特に以下は後続の研究・設計・実装へ渡す。

- 会話や手当てで相手へ自動的に近づき、複数の参加者の時間と中断をそろえること。
- 地域をまたぐ連続した移動、実際の運搬、救助と、場所ごとの在庫の全面的な接続。
- 中断した仕事の待ち列と再開順、設備・資材・人手を同時に扱う計画。
- H2/H3の建築計画、資材の搬入、施工と修繕、そこから生活条件へ返る効果。
- 大人数、複数拠点、所有・雇用・訪問者・警備などの制度と、各人の好みや関係による居住体験の違い。
