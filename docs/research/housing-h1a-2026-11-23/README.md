作業日：2026-11-23（クライアントの台湾日付）。基準はGitHub main `9e990947de72600a0f7711e51d1f12aa856a5949`。

## この変更で扱う範囲

`src/reform/spatial/` に、実際の場所、移動中の区間、設備の予約と利用、人物・物品の運搬、途中取消、独立形式での保存を扱う共通処理を追加した。旧V1保存を変更せず、部屋・家具・人物・接続の対応表を作る読み取り処理も含む。

H1-Aは本体で利用するための独立モジュール。現在の画面からこれらの新しい行動を指示する機能、旧Taskの実行方式の切替、製品セーブの移行はH1-Bの対象である。新しい住居システム全体が遊べる状態になったという完了報告ではない。

完成像はThe Sims 4・Kenshi・RimWorldと他のテキストゲームを学び、生活、仲間、建築、生産、冒険、戦闘、社会を結び付けるシミュレーション・ストラテジーRPG。現在の名称、画風、人数、家の数は完成形の制約にしない。

## 確認する行動の意味

| 場面 | 基盤が守る規則 |
| --- | --- |
| 設備へ行く指示を出す | 予約を確保するが時計も人物の実位置も進めない |
| 2分移動して2分利用する | 2分目に到着し、利用の完了は4分目。到着した分を利用時間へ重ねない |
| 道はあるが入室を許されない | 物理的な通行不能と、入室許可の不足を別の理由として返す |
| 移動中に戸や道路を閉じる | 既に入った区間は残り時間を消化し、次の区間へ入る前に新しい条件を確認する |
| 運搬を予約した相手が仕事を始める | 相手の仕事・予約を消さず、保存した引取り地点で待つ |
| 運搬対象が引取り前に移動する | 遠方から引き寄せず、元の引取り地点で待つ |
| 人物を運ぶ | 人物の所在を運搬者への参照で表す。運ばれている人物自身の新しい指示は受け付けない |
| 区間の途中で取り消す | 現在区間の終点まで退出し、そこで下ろして予約を解除。取消の完了を一度だけ通知する |
| 取消途中に保存する | 再開しても元の目的地へ移動せず、利用や配達を再開しない |

区間の閉鎖は、進入済みの人物が退出するまでの扱いを抽象化している。占有中の建物を削除するAPIや、壁の完成・撤去を待たせる施工処理はこの段階では追加しない。

## 旧保存を守る読み取り

`projectLegacyHousing` は現在状態 `game` と開始状態 `origin` を既存の検証処理で確認し、入力全体を複製した `source` を保持する。部屋を勝手に並べ替えず、家具の元のマス、旧リンクと室内の戸を保持する。

旧人物の記録には室内の正確なマスがないため、入口へ配置したことにはしない。人物の位置は `legacy-unspecified` として、分かっているlocation/roomだけを示す。途中の料理、予約量、所持品、外見、乱数を読み取りのために消費・再実行しない。片方のGameだけが不正な場合も全体を拒否する。

## 参考作品からの学習

[公式資料の再照合](reference-check.md) に確認できた挙動、資料の日付、取得経路、未確認事項をまとめる。EAの区画ごとの入場条件と勤務到着後の行動、Kenshiの運搬・就寝状態に関する過去の修正、RimWorldの移動・取消に関する修正を、確認すべき境界へつなぐ。

本作のマス表現、一分の時間単位、予約の持ち方、運搬者参照、途中取消後の退出は本作の設計判断であり、参考作品の内部実装を確認したものではない。Kenshiの旧パッチ履歴は1年以上前の資料として扱う。

Context7では実際のTypeScript 5.9.3に対応する公式コンパイラ検証例を照合した。種類を示す項目による状態分岐と、外部JSONを実行時に検証する処理を分ける。型宣言だけで保存の整合が保証されるとは扱わない。

参照した公式コード：[unknownの型検査例](https://github.com/microsoft/TypeScript/blob/v5.9.3/tests/baselines/reference/unknownType2.errors.txt)、[制御フローと別名の検査例](https://github.com/microsoft/TypeScript/blob/v5.9.3/tests/baselines/reference/controlFlowAliasing.errors.txt)、[部分型と絞り込みの検査例](https://github.com/microsoft/TypeScript/blob/v5.9.3/tests/baselines/reference/strictSubtypeAndNarrowing.errors.txt)。これらはコンパイラの検証資料であり、本作の保存の意味を保証する資料ではない。

具体化した受付・時間・予約・保存の扱いは、[実装中の判断記録](decisions.md)に理由と変更時の影響を残す。

## 続くH1-Bで接続すること

1. 最新の参考資料と現行コードを再確認し、旧Taskを継続できる範囲と新しい段階式行動へ移す範囲を決める。
2. 到着前には設備利用・会話・共食・手当てを成立させない処理を、画面からの指示へ接続する。
3. 待機理由と再開・取消の操作を表示し、進行中・運搬中・取消途中の保存を画面でも確かめる。
4. 外見と人物作成の選択肢、game/origin、予約元を保持して、旧保存からの継続を確認する。

H2/H3の計画編集・搬入・施工はこの接続結果を使う。社会制度、複数拠点の運営、長期の面白さ、大規模性能は別途研究・比較し、現在の小世界のテスト結果から完成形の上限や優劣を確定しない。
