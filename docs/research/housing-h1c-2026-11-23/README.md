# H1-C：集まる・一緒に過ごす・一人ずつ離れる

着手2026-11-23、記録2026-11-24（台湾時間）。基準はGitHub main `656695adad9b93074d29d2bc2a8a55a1f91e9616`。H1-Bの実位置・移動・設備利用へ、個別の席を使う会話と共食を接続する工程。

目指すのはThe Sims 4・Kenshi・RimWorldとテキストシミュレーションから学ぶ、生活・人物・拠点運営・生産・建築・冒険がつながるシミュレーションストラテジーRPG。現在の名称、画風、人数、家の規模、画面構成は、完成形の制限にはしない。

## 増える選択

| 操作や状況 | ゲーム内で区別すること |
| --- | --- |
| 長椅子・丸卓・台所と食卓へ集まる | 人数だけを数えず、一人ずつ異なる利用位置と予約を持つ。家具の周囲に使える床が少なければ、実際の席数も減る。 |
| 別の部屋にいる人を含める | 先着した人は自席で待ち、最後の人が到着してから共同時間を使う。歩行時間を会話や食事として数えない。 |
| 揃った人で始める | 会話は二人、食事は一人以上が自席で利用できれば開始する。待つか先に始めるかを選べる。未到着者の取消は安全な区間退出まで保持する。 |
| 自分だけ席を離れる | 食事は残った人が一人でも続ける。会話は相手がいなくなれば終わる。発起人を特別扱いしない。 |
| 途中で通路・利用許可を変える | 移動や利用を妨げる理由を表示する。開始後の停止は各人の離脱までの残り時間を示し、条件が戻れば次の一分から開始・再開できる案内に変わる。集合には別の期限がある。 |
| 一緒に過ごした経験 | 実参加の時間から欲求と関係へ反映し、一定時間を一緒に過ごした相手の記憶を残す。部屋が同じだけの第三者には付けない。 |

## 基本の試し方

1. 二人以上の暮らしで、手の空いている住民を選ぶ。初期の「木工の二人」と長椅子で比較できる。
2. 生活画面の「一緒に過ごす」で、会話か食事、会場、参加者を選ぶ。席・食事数・到着見込み・参加できない理由を確認する。
3. 開始指示だけでは時計は進まない。時間を進め、個々の移動・先着待ち・利用を確認する。
4. 一人を選んで「この集まりから離れる」を使い、残った人の様子を比較する。食事を始める前と後では、食事の返却が異なる。
5. 集合途中や利用中に手帳へ保存し、再読込みや別の暮らしへの分岐でも同じ参加状態を引き継ぐ。

今回の食事は用意済みの共有備蓄を一人一食取り置く。最初に実際に食べた分で消費済みになり、食べる前の取消だけが返却対象になる。移動区間の途中なら、区間を出て取消が完了するまで返却を待つ。配膳や皿の運搬を実装した扱いにはしない。

## 時間と結果の試作値

利用時間は一人20分。集合期限は計画上の最長到着時間に15分を加え、開始後に実利用が15分続けて止まった人は離脱する。会話相手を待つだけの人も、実利用が止まっている時間として扱う。

停止時間が14分・1分・1分なら、現在の条件が続く場合の離脱までの残りはそれぞれ1分・14分・14分と表示する。許可を戻して会話できる二人が揃えば、その場で二人の案内が「次の1分から再開できる」に変わる。操作だけで時計や参加時間は増やさない。食事は一人でも再開できる。集合中・退出中・離脱済みには、開始後の停止期限を付けない。

食事は実利用1分につき満腹2.8、同時に他の参加者も食べた分には社交0.5。会話は実利用1分につき社交2。通常の時間経過による欲求低下は続き、実利用中の主目的だけ低下率を0.3倍にする。

同じ場面で重なった人物組は、一分ごとに両方向の信頼・親愛を0.1ずつ変える。その人から見た関係が宿敵（内部名rival）なら-0.1。5分の実重複で、その相手との記憶を一度付ける。記憶は通常+4、宿敵は-4、食事180分・会話150分。途中で離れても、すでに得た経験は残す。完了時に同じ回復や関係変化をもう一度付けない。

同じ種別・同じ相手の共同活動の記憶がまだ有効なら、新しい記憶を積み重ねず、値と期限を更新する。相手は人物IDで識別するため、同じ名前の別人は区別でき、会話と食事も別に扱う。20分連続と5分ずつ4回の比較では、欲求・関係・気分が一致し、各人の記憶は1件だった。期限は最後に5分の実参加を達成した時刻に応じて更新するため、この比較で同じ時刻にはならない。期限切れ後に再び5分共有すれば新たな記憶となる。出所のない古い記憶から相手を推測して統合・変更しない。

これらは本作の初期調整値。参考作品の数値の再現ではない。長期的に共食だけが最適になるか、反復で関係を上げる操作が単調になるかは継続試遊で調整する。今回の短い機能確認を、長期バランスの検証とはしない。

## 旧保存と進行中の仕事

以前の保存は従来の席配置を使い続け、最初に成立した共同指示で現在の暮らしだけを個別席の規則へ進める。進行中の旧予約の利用点が移動・消失する場合は開始を断り、人物と設備を表示する。指示を試しただけ、読んだだけでは移行しない。最初の朝originを遡って変えない。

Game.version1、手帳format2、保存キーv2、書出しの包み1/2を維持する。新版が旧保存を読めることと、古いH1-BのHTMLへ新しい共同活動の保存を持ち戻せることは別であり、後者は対応しない。保存候補を手帳全体で検証してから書く仕組みと、旧キーの保全を引き継ぐ。

最終レビューで、旧保存の室内位置が未確定かつ人物IDが `constructor` の場合に、集まりパネルを描けない問題を修正した。このIDは有効なまま、安全な位置判定を使って表示する。正規の書出し・取込と描画を回帰試験で確認している。

停止後の同席履歴や会話相手不足の停止時計を人為的に消した入力は、記録から不可能と分かる場合に読込・取込・書込み前検査で拒否する。未変更の正規保存が壊れていたという指摘ではない。通常の停止保存からの再開、停止時間が違う参加者、時計を進める前の許可変更、相手が直前に完了・離脱した境界を受け入れる対照試験も通っている。各分の全履歴は保存していないため、複数の正規の経過が成り立つ記録を推測だけで拒否しない。

「次の完了」は現在の作業が完了または取消完了で解放される最初の境界を見積もる。集合から利用へ移っただけでは止まらない。通行条件を変えずに進めた場合の見込みであり、将来の新しい指示や許可変更を予言する表示ではない。
