## 標準ブラウザ検証と代替経路

`npm run test:standalone`、`npm run test:ui:standalone`、`npm run test:ui:bed-preference` は、いずれもローカルChromiumの起動時に `socket() failed: Operation not permitted` と `ptrace: Operation not permitted` で終了1となった。HTMLを開く前の失敗であり、画面の合格に数えない。既知の起動制約を繰り返し試していない。[PCログ](evidence/logs/standard-pc.log) ／ [モバイルログ](evidence/logs/standard-mobile.log) ／ [寝床ログ](evidence/logs/standard-bed-preference.log)

管理Chromeでは、SitesのプレビューCLIが返した開発用URLに、ビルド済み単体HTMLと同じファイルを置いて実際に操作した。ソース開発サーバーを試遊した結果とは区別する。標準脚本が起動前に作った有効な制御入力と[家具ID・期待表示の一覧](evidence/bed-preference-manifest.json)を使い、通常の作成経路と境界条件を別々に確認した。

このブラウザには独立コンテキストを作る機能がなく、開発用の既存保存61枠が残っていた。そのため、変更前の原文を私有の検証領域に保全し、新規の検証枠だけで操作した。公開Sitesの保存は使っていない。この代替判断と誤った場合の影響は[判断の記録](decisions.md)に残す。
