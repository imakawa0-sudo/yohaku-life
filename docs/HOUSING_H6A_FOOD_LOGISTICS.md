# 住居H6a：一束の食材の保管・運搬・料理

2026年11月26日（Asia/Taipei）。H5aの一室の寒さ対策、料理設備指定、工事用の現物運搬を維持し、共同備蓄から一束を取り分ける範囲を採用した。これは広いH6「収納・物流・工房」の最初の一周であり、その全体を完成させる変更ではない。

## 何が遊べるようになったか

1. 「住まい」の「食材の保管と運搬」で部屋と歩ける床を選ぶ。無料で指定でき、選択だけでは時計・物資は変わらない。
2. 共同備蓄の食材2を野菜の一束に取り分ける。居間の入口 (`living/0`) に現物が現れ、共有食材から2を引く。供給口自体を保管先にはできない。現存できる束は一つ。
3. 空いている住人へ保管先への運搬を指示する。現物を拾い、運び、下ろすまで実時間がかかる。運搬と料理は別の人に任せられる。
4. 「暮らし」の基本料理で材料に一束を、設備にかまどまたは台所を明示指定する。保管済みである必要はなく、供給口や中断時に残した床からも利用できる。現物が使用床にあれば、拾得・運搬を省き、本人が移動して料理する。
5. 搬送が済んだ次の分から既存の料理が進み、完成時に一束を消費して食事と経験を一度だけ得る。完成食は共同備蓄へ入る。従来の食事や携行と接続する。
6. 予定を変える場合は担当を外す。現物は元床・現在の床、通路途中であればその区間の終点に残り、料理途中なら使用床に残る。共同備蓄へは供給口への実搬送または供給口での明示返却によってのみ戻る。消費・返却後は次の一束を作れる。

共同備蓄を材料とする料理は従来どおりで、自主料理や上位料理も勝手に一束を使用しない。新しい材料選択は基本料理 (`work/cook`, `work/cook:easy`) に限る。現物を選んだままその束がなくなった場合、共同備蓄へ勝手に切り替えず、利用できない理由を示す。材料・設備の選択はタブ往復で保ち、住人や保存枠の切替で初期化する。

### 物資、予約と保存の境界

`HousingRuntime.foodLogistics` は任意項目で旧保存には新設しない。位置は `housing.state.items` の現物だけが持ち、台帳は束と注文を照合する。工事用現物との所有ID集合は、実際の `state.items` と完全一致させる。一束料理の `Task.reserved` は空なので、共有食材を重ねて引かない。搬送中にも束と料理席を確保し、別の食事席まで塞がない。取消・危険・許可不足で料理結果を得たり、食材を瞬間返却したりしない。返却や新経路の完成食が既存の数量上限を超える場合も現物を消失させない。保存は旧形式を維持し、現在状態と最初の朝の双方を検証する。

閉じた通路で待機し、開通後に続けることと、必要な入室権を失って安全に解除することを分ける。独立レビューで拾得後の経路に指示時点の退出権が持ち越される問題が見つかった。拾った部屋を起点に入室権を判定する修正を行い、保管・返送・料理の拒否と合法な一方向の運搬を試験し、再レビューで解消を確認した。最終統合レビューで、保管済みの束の返送不能理由が担当候補と返送ボタンから消える問題を発見した。保管床に束がある場合は候補に返送方向の理由を示し、住人を選んで各方向の理由を確認できるようにした。実行は従来どおり本体の予告と検証で制約し、開通後の回収まで最終版で再試遊した。
