# 私室の食卓に一人を招く

アオとミドリが普段使う寝室に、三人が座れる丸卓を置いた。もう一人の同居人アカとここで一緒に食べたい。これまでは部屋の利用者を変える必要があり、食事を始める前には、アカに寝室の本棚や裏庭への通路も開くことになった。食後に普段の利用者へ戻すまでが別の操作だった。

## 既存の間取りで試したこと

08:00に食事10食を持つ同じ三人から始めた。寝室にはアオ専用のむしろも置いた。席数は、実際に丸卓の隣まで歩いて座れる位置の数で決まる。

| 08:00の選択 | 食事の結果 | 住人の利用範囲 |
| --- | --- | --- |
| 寝室でいつもの二人が食べる | 08:25終了、残り8食 | アカは寝室の食卓・本棚を使えない |
| 寝室を開放して三人が食べる | 08:27終了、残り7食 | アカは本棚・裏庭への通路も使える。アオ専用の寝床は使えない |
| 三人の食後に寝室の許可を戻す | 08:27終了、アカはそこから7分で居間へ退出 | 退出後の再入室はできない |
| 三人が座れるように居間の丸卓を配置する | 08:23終了、残り7食 | 寝室を開放せずに食べられる |

居間でも使える席が二つしかない配置では、三人の指示は受理されなかった。家具を配置し直す費用と時間はこの比較に含めていない。普段の利用者を集合前に元に戻すと、入室できないアカの一食が戻り、会食の記憶を得たのは実際に参加した二人だった。

この比較から、私室での一回の会話か食事に、普段はその部屋を使わない同居人を一人招く範囲を選んだ。H7で予定する所有・入退居の仕組みは、帰宅先や維持を誰に頼むかを含めて検討を続ける。地域の人物を本当の来訪者にするには、家での実位置と退出の扱いも必要になる。[住居ロードマップ26](https://app.notion.com/p/42111141cb3681d98e7bf16736f536fd)

## 一度の招待で何が変わったか

「暮らし」の「一緒に過ごす」で会話か食事、会場、参加者を選ぶ。参加者の中に、普段からその部屋を使える人と、ふだんは入れない人が一人含まれる場合は、その回だけの招待を選べる。招待を選んでから実行するまでは、席・時計・食事は動かない。招かれた人が使えるのは、自分に予約された席。寝室に置いた本棚とアオ専用の寝床は使えない。

三人を同じ私室の丸卓へ招いた比較では、アオとミドリは5分、アカは7分歩いて自席へ到着し、その後20分いっしょに食べた。08:27に3食を消費し、三組が互いに同席した記憶を持った。部屋の普段の利用者は終始アオとミドリの二人だった。アカは食後、自分の足で室内から出口へ向かえる。居間に出てしまえば、次の招待を受けるか普段の許可が変わるまで再入室できない。

招待は集まりの指示時に出すので、招かれた人が先に着くこともある。別の配置で、客は5分、招いた人は9分かけて着いた。席で一人待った4分間には、会食の利用時間も二人の共有記憶も発生しなかった。招いた人が合流前に離れた条件では二人の食事が戻り、共有記憶は生まれなかった。5分間一緒に食べた後で中止した条件では、すでに食べた分と実際に同席した経験が残った。[招待・常設許可・共用室の比較](../scripts/compare-gathering-guest.mts)

## 参加を取り消したとき

招いた人が参加をやめると、一回限りの許可も終わる。会食の途中で客を部屋の普段の利用者に加えていた場合は、客自身の許可でそのまま参加できる。残り一人の会話は終了し、一人でも食べられる食事は残った人が続ける。「この集まりから離れる」と「現在の予定を取り消す」の両方で、選んだ人以外に誰が離れるか、未使用の食事がいくつ戻るかを確認できる。移動中の人は区間を出てから予約を解く。

食事の受取上限に近い状態では、別の人の料理が先に完成しても、まだ食べていない参加者の分を取り消して戻せる空きを確保する。以前の保存ですでに上限まで食事が積まれていた場合は、入りきらない取り置き分を「返却待ちの食事」に表示する。本当に一食を食べるなどして空きができると、その分だけ共同備蓄へ戻る。再読込や取り置きのやり直しで食事は増えない。[備蓄上限と取消を再現する試験](../tests/reform-gathering-meal-refund.test.ts)
