# 住居の家具を選んで使う：設計

2026-11-24（台湾時間）。H2/H3の次の工程。前回の[引き継ぎ](../../research/housing-h2h3-2026-11-24/next-handoff.md)に沿い、同じ朝から増築室と既存室への家具投資を比べ、実際の使い道を選べるようにする。ユーザーの「次の開発に進んでください」を受け、以下は開発側で具体化する試作判断であり、完成形の固定ではない。

## 目的と現在地

一室を建てて家具を置いた後に、「誰が、どこの家具を使うか」を指示前に判断できるようにする。現状の `planHousing` は到達できる空き席から移動＋利用の合計が最短のものを選ぶ。生活画面の予告は合計時間だけで、選ばれる家具と部屋は開始後まで見えず、同じ用途の遠い家具を直接指定できない。

対象は自宅の住居移動を有効にした暮らしにおける6種類の生活行動（食事、用足し、身支度、休息、交流、楽しみ）。既存の設備、予約、実移動、実利用、共通時計を使う。木工作業は現時点で住居設備を利用せず、料理はかまど／台所へ移動して使う。今回は生活設備の選択を先に扱う。

## 比較する方法と選択

| 方法 | 得られること | 負担・限界 |
| --- | --- | --- |
| 自動選択のまま、選ばれる家具名だけ表示 | 小さい変更で行き先が分かる | 増築室の同用途家具を使いたい指示は出せない |
| 自動を既定に保ち、指示ごとに家具を選び、移動と利用を分けて予告 | 今ある予約・経路・効果を使い、配置の違いを選択と結果で比べられる | 各行に選択欄が増える。恒久的な私物・寝床割当ではない |
| 私室・専用寝床・好み・部屋環境を一緒に追加 | 人物ごとの居場所や長期の住み分けへ進める | 所有・生活時間・環境効果の設計が同時に必要で、今回の比較原因が増える |

第2案を採る。自動で十分な時は従来の一押しを保ち、配置を使い分けたい時だけ家具を選ぶ。第1案の情報表示も含める。第3案は今回の実測を後続の判断材料にする。

## 挙動

### 家具と席

- 各生活行動に「自動（移動と利用が短い設備）」と、その用途に対応する全家具を並べる。部屋名・家具名・家具のマス位置で同じ名前の家具を見分ける。
- 家具を選ぶと、その家具の中の到達可能な空き席から従来と同じ規則で選ぶ。席番号をプレイヤーに選ばせる機能や待ち行列は追加しない。
- 選択した家具が予約済み、許可なし、通路閉鎖等で使えない時は理由を表示し、別の家具へ勝手に置き換えない。別の設備への選び直しと「自動」はプレイヤーが選ぶ。
- 予告に部屋・家具・移動分・利用分・合計分、食事なら取り置く食事1を示す。時間は現在の状態での見込みで、後からの通路変更等による待ち時間を保証しない。
- 家具が削除された場合は「選んだ設備がありません」と知らせて実行を無効にする。別の人物または保存枠に切り替えた時は未確定の選択を自動へ戻す。時間送りや他人の予約変更では選択を保ち、可否を再計算する。
- 外出中や住居未移行の旧方式では従来の行動欄を維持し、この選択欄を出さない。

### 指示と保存

`order` / `inspectOrder` に指示専用の `home-use` と家具IDを渡す入口を加える。家具IDを配列から厳密に照合し、その用途の既存 `need` 作業として開始する。既存の `target`（欲求の種類）、`station`（席）、`room`、`spatial` をそのまま保存する。`home-use` という新しい保存作業種や選択専用の永続項目は作らない。

予告と実行は同じ候補探索・予約規則を通す。表示の計算は時刻、資源、乱数、予約、作業、原点を変えない。無効な指示は元の作業と資源を維持する。重傷時の休息等は既存need行動の許可と同じにし、危険時の禁止や移動区間途中の安全制限を回避しない。

既存の自動行動の選択順、効果、予約期間、利用許可、取消の安全退出、食事会・共同会話、工事は変更しない。家具を指定した後に通路が閉じれば既存の待機となり、取消も既存の解除と返却を使う。

## 共有する制約

- 画面の選択・予告・指示予約では時計を進めない。移動・待機・実利用は既存の共通時計で計上する。
- Game version 1、Library version 2、保存キーv2、書出しenvelope 1/2、Housing version 1を維持する。originと旧保存、外見10項目41値を保持する。
- 新しい依存、部屋名による性能効果、家具の費用・利用時間の変更、私物割当、倉庫容量、工房専用生産、招待・承諾は今回含めない。
- PCと320/390pxの表示で理由と操作が読めること。現行の日本語・4タブ・人物作成の選択肢を保つ。
- GitHub mainとNotionに実装・検証・次の問いを保存する。Sites本番は更新しない。

## 受入と比較

1. 同じ「木工の二人」の08:00を原点に、同じ家具を新室／既存室に置く。工事の材6と実施工30分、運搬と移動、家具の費用、利用者の位置、もう一人の仕事を記録し、翌朝まで比べる。初回比較は現行の自動選択、その後は明示指定も試す。根拠のない部屋ボーナスで投資の利益を作らない。
2. 近い既存家具と遠い指定家具がある時、指定した家具へ実到着して利用し、従来の自動は従来の候補を選ぶ。複数席では他人の予約と競合せず、完全予約・許可不足・経路閉鎖・存在しないIDを説明する。
3. 予告を繰り返しても全状態が同じ。指示時点の時間・資源予約、実利用の効果と完了の一回性、移動途中・利用途中の書出しと再読込みを確認する。originを保ち、同じ続きを再現する。
4. 生活画面で自動／指定、忙しい家具の理由、通路閉鎖後の待機・再開、人物と保存枠の選択初期化を実際の単体HTMLで試す。
5. 既存全件試験・型検査・ビルド、必要な新規試験、独立レビューを通す。標準Chromium起動が環境制約で使えない場合は記録し、利用可能な管理Chromeで最終HTMLを直接操作する。実機・Safariの未確認を区別する。
