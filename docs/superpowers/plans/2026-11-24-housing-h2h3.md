# Housing H2/H3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 計画した一室へ実物の木材を運び、担当を替えて施工し、完成後に入室・設備利用できる一周を保存と取消まで通す。

**Architecture:** 既存SpatialStateのcarry/useを住居の工事台帳へ接続する。材料の位置はitem、会計と累計施工は計画、現在の作業はTask/SpatialOrderへ分け、往復検証する。完成は計画IDから現在の家へ差分追加し、既存編集の安全検査だけを共用する。

**Tech Stack:** React19.3.1 / TypeScript5.9.3 / Vite7.3.8 / Node test+tsx / Playwright1.65.1。依存追加なし。

**Spec:** `docs/superpowers/specs/2026-11-24-housing-h2h3-design.md`

## Global Constraints

- Game.version=1、Library.format=2、保存キーv2、書出しenvelope1/2、HousingRuntime.version=1を保つ。constructionは省略可能なversion1拡張。読込・表示で作らない。
- 現在のgameだけを変更し、origin、旧作業の予約・残時間、外見10項目41値と描画素材を保持する。
- 計画・予約・担当割当・取消・設定・表示では時計を進めない。実進行は既存advanceの一分処理に集約する。
- 材料の所在は空間itemだけに持ち、共有備蓄、cargo、Task.reservedへ同時に置かない。二重消費・二重返却を禁止する。
- 通過・退出の許可を、持上げ・施工の許可へ流用しない。危険中またはinjury>=70では新しい運搬区間と施工を開始しない。進入済み区間は安全に終点へ出る。
- 旧保存は読み、未知の破損データは拒否する。辞書はown-propertyで参照し、有効な人物ID constructorを保持する。
- 一室4×3、木材6、実施工30分、未解決一件（取消残材の回収待ちを含む）は今回の試作範囲。部屋名だけで用途効果を付けない。
- 既存の家具・壁・既存室拡張・共同活動・時計・通常行動を保つ。Setupの初期家編集を保つ。開始後の新室は工事を経る。
- 本番Sitesを更新しない。承認済みのGitHub main差分保存とNotion記録更新はcontrollerが行う。

## Review Focus

- 運搬を止めた瞬間に供給口の束を削除し、移動中orderが欠損payloadを指さないこと。Task1の取消途中保存で固定する。
- 部屋の退出権だけで材料を扱えず、持上げ後に許可を失っても新しい区間へ入らないこと。Task1の許可取消試験で固定する。
- H1-Cの初回layout2移行や別人の部屋移動が工事slot/束を消さないこと。Task2の横断試験で固定する。
- 工事中の別家具編集と自由木材0が、完成時の全家上書き／二重課金を起こさないこと。Task2の差分完成試験で固定する。
- 回収待ち・不可能な担当・完成反映待ちを小画面でも再開でき、実際の保存結果が同一Gameへ戻ること。Task3の操作試験とcontrollerの実ブラウザ確認で固定する。

## File responsibilities

`constructionTypes.ts` は計画と材料型・試作定数、`construction.ts` は公開の純粋コマンドと検査、`constructionProgress.ts` は一分境界と安全解除、`constructionValidation.ts` は未知入力と往復関係、`constructionTopology.ts` は工事のslot/取扱許可/保護地点、`constructionPresentation.ts` は場所・段階・実経路予測を担当する。既存runtime/bridge/simはこれらを接続し、巨大な別エンジンを作らない。UIは `ConstructionPanel.tsx`、既存画面の入口だけ `ReformApp/HouseEditor/Life/HousingPanel` に追加する。

設計上の問いはcontrollerへ報告する。明確な小関数の配置は各ファイルの責務内で決めてよい。実装者は自分のTask以外を進めず、他のagentをspawnしない。全体試験は各Task完了時に一回、編集中は関係する試験だけにする。

## Controller completion

各Taskは新しいimplementer→差分付きの独立task reviewで進める。controllerは研究と設計文書、実ブラウザで同一HTMLの通常一周/制御境界、保存export照合、全体レビュー、一回の最終修正波とscope限定再レビューを担当する。本文と成果物の一致を確かめてから、既存main treeを基礎に変更ファイルのみGitHubへ保存し、読み戻す。Notionの新規結果ページと現在地・住居ロードマップ・候補を更新し、履歴と後続を残す。すべてのRulingを最終報告へ集める。
