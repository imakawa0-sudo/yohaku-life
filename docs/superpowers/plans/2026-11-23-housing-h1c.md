# Housing H1-C Shared Activities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Residents gather at separate real seats, talk or eat prepared meals, leave individually, and safely save every stage.

**Architecture:** Preserve the existing geometry as the default and introduce an optional layoutVersion: 2 when a shared command succeeds. Each resident owns a normal spatial use order; a separate shared activity coordinates waiting, actual participation, effects and termination. Keep coordination, validation and presentation separate from the existing large simulator.

**Tech Stack:** Existing package ranges React ^19.1.0, TypeScript ~5.9.3, Vite ^7.2.2, Node test runner with tsx. Installed versions checked: React/React DOM19.3.1, TypeScript5.9.3, Vite7.3.8, tsx4.23.15, Playwright1.65.1. No dependency upgrades.

**Spec:** docs/superpowers/specs/2026-11-23-housing-h1c-design.md

## Global Constraints

- Game.version=1、Library.format=2、保存キーv2、書出し包み1/2は維持する。
- originは変更しない。失敗なら移行・人物初期位置・食事取り置き・活動IDの消費も公表しない。
- 指示では時計を進めない。世界時間は既存advanceだけが進める。
- 旧手帳、gameとorigin、外見10項目・41値、旧途中作業を維持する。
- 利用20分。集合期限は指示時刻＋計画上の最長到着時間＋15分。
- 開始後15分続けて実利用がなければ、その人を個別離脱へ移す。
- 食事の実利用1分で満腹を2.8回復。同時参加がある分の社交は0.5。会話の実利用1分で社交を2回復。
- 同時に実利用した人物組の信頼・親愛を双方0.1、本人から見たrivalなら-0.1。5分で記憶を一度、値は通常4/rival -4、食卓180分・会話150分。
- 完了時に同じ回復を再付与しない。途中離脱でも既に反映した実参加分は残る。
- 今回は途中からの新規招待・加入、心理的承諾、予定表、建築施工を追加しない。Sites本番公開は含めない。

## Review Focus

1. A valid legacy second-seat reservation would move in layout 2: reject the attempted upgrade atomically and leave origin, admitted transit and IDs unchanged (Task 1).
2. Input participant order or a constrained route changes greedy seat assignment: search complete matchings and use deterministic max ETA / sum ETA / lexical ties (Task 2).
3. A participant is withdrawing while the rest finish and reuse seats: retain only the old person's live reservation until its safe exit, without touching new reservations (Task 2).
4. A terminal participant's historical seat vanishes during permitted editing: validate history separately from live geometry, while preserving live reservations and current positions (Task 2).
5. A save/reload at the fifth overlap minute or an invalid replacement repeats memory, refunds consumed food or loses membership: preserve exact accounting and transactional replacement (Task 2; real UI save cycle Task 3).
