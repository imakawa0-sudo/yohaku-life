## 小さくしたときの処理

直接縮小では、alphaが16未満のほぼ透明な画素を派生画像だけから除き、縦横比を保って最も近い元の画素を採用する方式（nearest）で縮小した。A/G/H/Iと衣装4種はそれぞれ共通の切出し範囲を使う。ぼかす方式との比較では、nearestの方が輪郭と細部を読み取りやすかった。

ゲーム用の部品はalpha 128以上を不透明に揃え、肌・髪・布などを別々の8段階の色へ変換した。組み替える髪で隠れなくなる額を補い、目、傷、そばかす、眼鏡、年齢差を小さい格子上で描き直している。全身は約5頭身の成人の姿を基準に、カヤの身体とスイのがっしりした身体を使う。細身体格と4衣装の全身差分は、この原画由来の身体へ合成する。

胸像は48×56、全身は26×60で描画する。既存UIが必要な倍率で表示し、背景・影は従来の呼出元が描く。原画PNGをページ表示時に読み込まないため、大きな元画像の転送や非同期の読込待ちは発生しない。直近128描画を再利用し、選択肢を戻したときにも同じ画素を返す。

## 再生成と検証

通常のゲーム開発は、チェックイン済みの部品データを使用する。

```bash
npm ci
npm run test:characters:unit
npm run build
npm run test:characters
```

`test:characters` はビルド済み単体HTMLを独立したPlaywright/Chromiumで操作するスクリプト。今回の実行環境ではChromiumのソケット作成が `EPERM` となり、開始できなかった。スクリプトを実行済み・成功済みとは扱わない。今回実施した内部プレビューでの操作は下記の記録に分けた。

画像部品を再生成する場合だけPython・Pillow・NumPyを使う。使用バージョンと入力hashは生成記録に残す。

```bash
python scripts/convert-character-originals.py
python scripts/build-character-layers.py
python scripts/convert-character-originals.py --check
python scripts/build-character-layers.py --check
```

本体テストは `node --import tsx --test tests/*.test.ts` でも実行できる。今回はこちらを使った。実際の操作・保存の照合・画面寸法・限界は [試遊記録](../../PLAYTEST.md) と [browser-qa.json](browser-qa.json) に記載する。
