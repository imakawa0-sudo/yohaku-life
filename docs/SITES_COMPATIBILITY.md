# Sites 配布データの適合性確認

2026-11-19。公開形式・保存された画面・ゲーム本体の前提を確認した記録。

## 結論と根拠

通常の公開入口は Sites の静的サイト形式に適合している。React やゲームデータの規模を理由に Sites で開けない構成にはなっていない。

- `.openai/hosting.json` は既存の `project_id` と `static.directory: "dist"` を持つ。
- 配布には manifest、`dist/index.html`、参照される JS/CSS、一枚 HTML が含まれる。通常の入口はコンパイル済み JS を読み、開発用 TSX を直接読まない。
- 本体に API サーバー・Node.js 実行・ローカルフォルダへの依存はない。保存はブラウザ内か JSON ファイルで行う。
- Sites が保持する公開版2の source commit は `9ce89a0beb7f97cca61c13983e896e2ee0f54603` で、直前の修正版と一致した。保存アーカイブのファイル数は5。送信アーカイブ内の全ファイルは手元のビルド成果物と一致した。
- 公開版2の Sites 保存画像を取得し、実際にゲームの初期画面が描画されていることを目視確認した。新しい住民チェック欄・選択人数・物資4種も表示されている。[確認画像](screenshots/sites-published-v2.jpg)
- Sites のエラー専用ログ取得結果は空だった。これはクライアントの全操作が成功した証拠ではない。

非公開サイトの認証は Sites 側が扱う。npm パッケージの `private: true` はホスティングの適否を変えない。通常 CSS の Google Fonts 読込が拒否されても端末フォントへ切り替わる。

## 実際に見つけて修正した不具合

### 一枚 HTML の CSS

`@import` を最初のセミコロンまで削除する処理が、Google Fonts URL 内のセミコロンで途切れていた。ダウンロード用 `yohaku.html` に不正な先頭文字列が残り、`:root` の CSS 変数が適用されなくなる問題だった。

引用符・URL括弧・コメントを区別して import 文全体を除去する処理へ変更した。引用形式や URL 内セミコロン、実際のゲーム CSS を使う回帰テスト4件を追加した。Sites の通常の入口 `dist/index.html` はこの処理を通らないため、この問題はプレビュー接続失敗の原因ではない。

### 不正な保存ファイル

人物間の関係へ未知の人物・自分自身などの余分なキーを入れた保存が検証を通り、住民画面の表示時に落ちるケースを再現した。読み込み前に不正キーを拒否し、既存の形式1と途中調理の保存がそのまま読めることを確認した。

## 確認の限界

共有プレビューは relay readiness のタイムアウト、ブラウザ操作ツールは起動環境エラーで接続できていない。公開時に Sites が保存した画像による初期画面確認と、操作を直接行うブラウザ試遊は区別する。今回、PC・スマートフォンで全操作を直接確認したとは報告しない。

`npm test` 45件（従来40件・保存検証1件・一枚HTML4件）と `npm run build` を実行して再配布する。表示を確認できた通常公開版を、根拠なく別フレームワークへ作り直す変更は行っていない。
